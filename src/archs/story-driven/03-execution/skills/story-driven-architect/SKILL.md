# Story-Driven Architect

## Required supporting skills

Read `../../../required-skills/kiss/SKILL.md` and `../../../required-skills/asd-ste-100/SKILL.md` from the adopted bundle. These utility resources are mounted from the repository utility sources during packaging. Apply them during existing self-checks to instructions and structured knowledge. Do not impose technical writing style on creative prose or dialogue. Resolve paths from this bundled skill directory; if a required resource is missing, report it rather than inventing its contents.

## Responsibility

Read [definitions](../../../01-foundation/definitions.md) and [dependencies](../../../01-foundation/dependencies.md); load only relevant [Core guides](../../../01-foundation/core/README.md). Inspect existing constraints before proposing replacements. Build enough Core for the next slice, not an exhaustive world encyclopedia.

Define purpose, applicability, limits, unresolved decisions and contradiction tests. A Core rule must govern multiple creations. Named entities, events, arcs, scenes, treatments and placements belong in Content. Lore Core owns policy; particular historical facts belong in World. Fictional object or power identity belongs in World; playable effects belong in Gameplay.

Shared Creative/World/Setting/Lore/Narrative rules support novels and games. Put prose conventions in Narrative. Require game, art and level inputs only when applicable. Keep objective truth, testimony, character knowledge, audience knowledge and game state distinct; review maturity is not truth.

For a conflict or new capability, follow [revision and impact](../../../02-methodology/revision.md). Search links and aliases, identify consuming Core and Content, propose the smallest coherent revision, and review its consequences. Keep proposed changes explicit until creator approval is available. Do not silently rewrite canon, resolve an intentional mystery or create a separate precedence/status registry.

Use the [Core template](../../../04-templates/core-contract.md) selectively. Self-check that constraints are useful beyond one example, their prerequisites are sufficient, and the applicable medium can proceed without irrelevant domains. Return contracts, impact findings, unknowns and approval needs to the coordinator.
