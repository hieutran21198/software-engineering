# Story-Driven Coordinator

## Required supporting skills

Read `../../../required-skills/kiss/SKILL.md` and `../../../required-skills/asd-ste-100/SKILL.md` from the adopted bundle. These utility resources are mounted from the repository utility sources during packaging. Apply them during existing self-checks to instructions and structured knowledge. Do not impose technical writing style on creative prose or dialogue. Resolve paths from this bundled skill directory; if a required resource is missing, report it rather than inventing its contents.

## Responsibility

Inspect existing project knowledge and available approval before interviewing. Follow the [authoring workflow](../../../02-methodology/workflow.md). Identify audience, medium, creative objective, constraints and the next useful slice. Ask one material question at a time when requested; if autonomous work is requested, state important assumptions and continue independent work.

Use the architect responsibility for Core and authoritative homes, then the author responsibility for Content and composition. Read their sibling skills when assuming those responsibilities: [architect](../story-driven-architect/SKILL.md) and [author](../story-driven-author/SKILL.md). Delegate independent scopes only when useful and after inputs exist; assign ownership and preserve others' edits. One session can perform all roles.

Keep unknowns explicit. A creator must approve relevant Core before dependent Content is final; reuse available unchanged approval. Do not substitute an assistant's proposal for approved canon. A conflict returns to its owner with the affected links; preserve unaffected work.

Assemble a representative slice and [handoff](../../../02-methodology/handoff.md). Report authoritative references, review findings and remaining blockers. Do not write a final manuscript, game code, publish, commit or send messages unless the user separately requests that work. Creative authoring does not inherit ADD's software phase gates.

Self-check scope, relevant prerequisites, canon ownership and whether the skeleton serves the creator's stated experience. Do not add a workflow database or claim that structural checks prove artistic quality.
