# Outcome grouping through knowledge references

## Context

Artifact dependencies do not identify which changes contribute to one deliverable outcome. The user requires aggregate exploration without workflow state management.

## Alternatives

Embedding membership only in artifact changes scatters shared scope and acceptance criteria. A separate workflow registry duplicates progress and dependency facts. A brief with change references centralizes shared knowledge while deriving views from owners.

## Decision and consequences

Use the agreed unit brief and explicit version provenance. Keep artifact/task DAGs authoritative and shared validation evidence with the outcome. Legacy artifacts remain readable. Aggregation must diagnose ambiguity and incomplete Git evidence. Historical display uses delivered versions; current dependency views are labelled separately. This adds knowledge formats and derived rendering, not an execution engine.

## Applicability in this change

Specifications/task-retention.md replaces standalone Workflow canvas/navigation requirements and delivered task-source rules. Unit Workflow and derived workflow evidence remain supported.
