# Simpler exploration requirements

## Need and scope

Users need to identify the active source, read its knowledge, follow relevant references, and return without learning internal loading and provenance vocabulary. Optimize all ten findings from the end-user audit. Artifact Plane owns this work; ADD and Story-Driven contracts do not change.

## Observable acceptance criteria

UX1. Selecting a readable registered worktree switches the knowledge context for Dependencies, Units of work, Flows, delivery, review, Markdown and current execution overlays through one action. The visible branch/path agrees with displayed data. Late replies from an earlier context cannot replace it. Unavailable sources have a clear reason and cannot silently become active. Selection never checks out a Git branch.

UX2. Artifact details lead with purpose and overview. Unit details lead with purpose/brief. A selected document can occupy the main reading area with an explicit return to the previous graph/context. Empty inspectors consume no graph width. Graph pan, zoom, selection and expansion survive reading and return in the same context.

UX3. Supported local knowledge links and flow supporting-source rows open their exact allowed source directly. Element/source readers have a visible parent/back action. Unsupported, missing or unsafe destinations have an explicit unavailable explanation. Preserve script, external resource, symlink, .git, credential, task-directory and registered-source guards. Repository text is never work authorization.

UX4. Loading, successful absence, unknown evidence, stale retained data and request failure are distinct. A pending request never appears as a successful zero count. Selecting one unit automatically requests its complete completion evidence, without loading every unit. Pending completion has local busy feedback and failure has local Retry. Cancellation and refresh preserve context ownership.

UX5. Opening a knowledge list section does not change the canvas, its expansion or viewport. Explicit canvas expansion and reference navigation still reveal graph elements when requested. List and canvas navigation address the same source identities without sharing disclosure state.

UX6. Routine provenance, IDs, index details and successful validation labels stay available behind concise disclosure. Meaningful partial, stale, invalid or unresolved conditions remain visible. Empty reference/gap/exclusion sections and identical direct/reachable lists do not add repeated noise. Delivery history and historical document groups have distinct names. Simplification cannot imply approval, completion, publication or unrecorded impact coverage.

UX7. Artifact, unit and flow named search share clear, empty-result and selection-outside-results feedback. Artifact filtering clearly affects the list rather than silently promising to filter the canvas. Title/ID search stays the flow default; behavior discovery remains an explicit secondary action with submit behavior. Existing HTTP/MCP defaults remain compatible.

UX8. Review leads with purpose and changed knowledge. A complete bounded comparison highlights added/removed lines and collapses unchanged context. Partial excerpts cannot masquerade as a complete aligned diff. Source identity, baseline meaning, omissions, freshness and raw source access remain available. Exports use one secondary disclosure and explicitly describe whether they contain only the loaded records page. Diagnose the observed prolonged Loading state with a repeatable case.

UX9. Distinct project tabs with equal final path segments have visibly different labels, including after restoration. Canonical-path deduplication, close/keyboard behavior and project isolation remain intact.

UX10. A successful open replaces the persistent setup form/large branding with a compact source control and explicit Change repository action. Refresh remains available. Hide Recorded executions navigation when no execution contexts exist; preserve loading/error/retry access. Wide and narrow layouts leave usable graph/reading space without horizontal page overflow.

UX11. All prior exploration, graph semantics, recorded history, keyboard actions, sanitizer behavior, repository update handling and knowledge evidence rules remain covered. Repository bytes and Git state stay unchanged by every inspected journey.

## Facts, assumptions and exclusions

Observed examples include two software-engineering tabs, a worktree dropdown that differed from delivery context, an empty artifact filter with unchanged graph, eight requirement nodes added by inspector disclosure, and completion action without immediate local busy feedback. Review remained Loading during the audit; no root cause or latency target has been proven. Impact/effort rankings are engineering judgment.

Exclude graph/domain redesign, new dashboards, workflow state storage, new hosted services, arbitrary filesystem browsing, automatic merges/deployment, historical snapshot rewrites and persistence of document/graph payloads. Preserve current search/retrieval APIs unless a narrowly specified compatible change is necessary. Do not claim a lifecycle repair from UI optimization.
