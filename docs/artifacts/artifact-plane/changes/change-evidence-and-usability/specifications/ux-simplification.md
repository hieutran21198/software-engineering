# Simpler exploration contract

Governs UX1–UX11. Reuse React, React Flow, the existing scoped query services, sanitizer, project tabs, shared search field and stylesheet. The browser owns navigation and request presentation; repository knowledge remains authoritative. No domain graph or evidence derivation changes are required.

## Source identity and one-step worktree switching

A project tab retains its canonical opened project root as the registered-worktree boundary and persistence identity. Its active source is one readable registered worktree. Use explicit projectRoot and activeWorktree identities rather than treating the unit-only selection as a global context. Every knowledge query uses path: projectRoot and worktree: activeWorktree. Flows and review use the same pair; the current execution overlay uses activeWorktree. Runtime/recorded identities are never rewritten to the current source. The repository banner describes the active worktree's branch, canonical path, HEAD and dirty state. Project path persistence and canonical duplicate-tab behavior remain unchanged.

Selecting a readable worktree is the explicit switch action; remove Open worktree. Abort the prior generation's reads, complete the target overview, then atomically install the complete target snapshot and context. Do not merge only the target's unit summaries into the old dependency snapshot. While opening, retain the prior view under its committed source label and expose Opening <target> with busy feedback. A failed switch leaves the previous committed source active and reports failure locally. Unavailable/non-ADD entries have visible reasons and cannot become active. Rapid selection A→B→C accepts only C's current generation. Switching never checks out or edits Git.

After success, retain the top-level view and dependency knowledge mode; clear source-specific review, unit, document, element, delivery, task and flow selections, requests and graph expansion. A stable ID that happens to exist in both worktrees does not prove identical context. No per-worktree graph payload cache is introduced. Observation, active refresh, source reads and runtime overlays follow the committed source. Project switching and closing cancel in-flight work as before. Repository-path replacement remains an explicit Change repository action separate from worktree selection.

Dependencies continues to use current-root declared dependencies; Flows Established continues to use its protected-ref baseline. Show these meanings in a concise snapshot-context disclosure rather than treating either as verified version establishment. Do not silently unify the underlying semantics.

## Reading and return

With no selection, omit the empty details panel and divider so the graph uses available width. Selecting an artifact shows its title, concise declared version/source, and rendered overview before knowledge navigation. Selecting a unit shows its purpose/brief first, followed by concise members and completion. Relationships, histories, criteria detail and provenance remain available in named collapsed sections; meaningful warnings remain visible. Use Delivery history and Historical documents as distinct labels.

Selecting a knowledge document opens a main-area reader with title, exact source and Back to artifact, Back to unit, Back to flow or Back to task as appropriate. Provide Back to graph for the graph that launched it. Retain the originating graph component/viewport and selection in browser memory while the reader is visible; do not refit, reconstruct or unmount it on read/return. A small in-session source navigation stack supports successive supported document links and Back; scope it to the active project/worktree and discard it when that context changes. Do not persist bodies or navigation history across reloads. A missing source shows a readable unavailable state and a working return action.

Keep graph node selection, references and provenance reachable from the reader without showing a second copy of the same Markdown in the inspector. The inspector remains resizable for selected graph details. At widths below 800 pixels, render the active reader at available page width; graph/detail layouts can stack. At 390, 700, 851 and 1440 pixels, controls must remain reachable without horizontal page overflow. Do not shrink the entire application to fit.

## Contained source navigation

Extend the existing Markdown presentation with an optional context-aware navigation callback and generated allowed-target map. Resolve relative Markdown paths against the exact displayed source, not the repository root or current-version shortcut. Normalize path segments, decode once, reject absolute paths, root escapes, schemes, .git/credential destinations and invalid encodings. A ../ segment is not rejected merely for existing; its resolved destination decides containment.

A target is navigable only when it identifies a root/current/change knowledge source, declared unit/evidence source or registered flow/review source already allowed in the active context. Resolve cross-artifact links only to discovered artifact/source identities and retain exact version/change selectors. Historical versions outside the known allowlist, external URLs, missing files and unsupported file types remain inert with an accessible unavailable reason and visible destination on demand. Never substitute a newer/current version for an exact unavailable snapshot. No new general filesystem endpoint, hosted link fetch or external resource load is introduced.

Render sanctioned navigation as locally handled controls backed by the trusted target map; repository-supplied event handlers, href schemes, forged data attributes and HTML cannot install callbacks or bypass the map. Keep DOMPurify and all current blocked tags/resources. Server markdown reads still validate declared scope, realpath containment, task-directory containment and UTF-8. Client resolution is a convenience, never the security authority. Server rejection produces local unavailable feedback and retains Back.

Flow support rows resolve to source IDs already returned by the selected detail response. Activating a resolved row opens that registered source directly through the existing flow source operation; unresolved support stays visibly unresolved. Keep a source selector only as a secondary browse-all affordance if it still serves a distinct purpose. Review source readers keep revision-bound registered IDs. Supported same-document heading navigation uses generated heading identities after sanitization; unrecognized anchors remain explicit unavailable destinations.

## Independent disclosure and explicit graph reveal

Keep canvas expansion and document-list disclosure in separate state sets with source-specific keys. Opening a list group or delivery history cannot expand or relayout graph nodes. Explicit Expand elements on canvas and selecting a resolved graph reference may reveal the required canvas groups. Selecting a document from its list opens the reader without adding nodes. Keep current-version and historical source boundaries, natural order and element IDs unchanged. Existing references still retain exact targets.

## Honest loading, completion and recovery

Use request states idle/deferred, loading, loaded, stale and error separately from evidence values unknown/inferred/documented. While a section is deferred/loading, show Loading evidence rather than Unknown phase or Task evidence (0). Show zero only after a successful read of an empty section. Previously loaded data remains readable during refresh, marked Updating or Stale as applicable. A repository-level Current label does not imply every section is loaded or evidence is complete.

Automatically request completion for the selected active unit only. Reuse the existing completion endpoint and exact complete publication/shared-evidence derivation. Deduplicate by project/worktree/unit/overview epoch; refresh invalidates only the selected evidence. Track local completion busy/error separately from graph section state. Show Checking completion… while pending, completion result after success, and a local Retry after failure. Remove the initial Load completion evidence action. Do not scan all units or conflate loaded graphs with complete completion proof.

Abort obsolete reads on project/worktree/unit selection, close, deactivation or replacement request. Use generation/identity checks on success, failure and finally callbacks. An obsolete completion response cannot install evidence under a new epoch. User-visible review, source, completion and section reads have a 30-second browser request deadline with an explicit timed-out message and Retry; cancellation is not an error. This deadline is recovery policy, not a promise that derivation normally takes less than 30 seconds. Avoid automatic retry loops. Diagnose the audit's review Loading behavior using a clean current server and delayed fixtures; record actual cause or remaining uncertainty. Refresh/reconnect must not endlessly reset a usable request before it can settle.

## Lower-noise browsing and shell

Use SearchField for artifacts as well as units and flows. Label artifact search Filter artifact list; match each normalized title/ID independently with trim/NFC/lowercase. Provide clear, no matches and selected-outside-results messages. Retain the graph for context and state that the list is filtered. Do not add a second global search service. Units keep immediate named filtering; Flows keep 250 ms named filtering and explicit behavior submission. Present Behavior discovery as a secondary action replacing the persistent search-mode dropdown; its return action is Back to title or ID. HTTP/MCP omitted match still means discovery.

Flow list rows lead with title and concise source/version context. Move repeated valid state, logical ID and creation date into details. Always surface invalid/stale/partial/unresolved conditions. Consolidate freshness, coverage and publication detail into one Evidence details disclosure with a concise visible warning when any condition limits interpretation. A fresh index is not full system coverage or version establishment. Hide empty References/Gaps/Exclusions, and show All reachable only when it adds identities beyond Direct; retain a way to inspect exact direct/transitive sets when they differ. Preserve every meaningful uncertainty and evidence reason.

After successful open, replace the large brand/setup form with a compact source bar showing project, active branch and Refresh. Change repository expands the existing labeled path input and Open action; Cancel returns to the compact bar without replacing the project. Invalid/missing restored projects retain the path input and recovery. The project tab bar stays visible. Hide Recorded executions only after a successful empty contexts read; while loading/error, retain compact feedback and Retry, and reveal it if observation later discovers recordings. No execution history is deleted.

For colliding project basenames, append the shortest unique parent-path suffix; use canonical paths as a deterministic final fallback. Full path stays in accessible tooltip/description. Do not use transient dirty state or branch alone as tab identity. Recompute on open, close and restoration; preserve stable tab IDs, keyboard order and canonical deduplication.

## Focused review and bounded comparison

Lead review with change title, baseline label, purpose/scope and changed-record navigation. Keep scope visible by default. Place captured hashes, revision internals, routine publication sources and export controls under concise disclosures. One Export context disclosure retains Copy Markdown, Download Markdown and Download JSON with current freshness guards; label these Loaded records page, with visible remaining-page/omission information. Preserve context packets and MCP/HTTP output formats.

Use a small pure line-comparison helper in the existing app; add no UI framework or diff service. Only align complete before/after source texts from offset zero with no remaining cursor/omission. Added/removed records have an absent side, not an empty unknown read. Render added/removed lines with text markers as well as color; show three context lines around changes and expand unchanged blocks on demand. Keep exact source identity and raw text available.

Bound complete comparison to 200,000 combined UTF-16 characters, 2,000 lines per side and 1,000,000 line-comparison work units. Exceeding any bound shows Comparison too large with raw source/excerpt access; it does not fabricate no changes or truncate an aligned diff. Use the existing source cursors for an explicit Load full comparison action when initial excerpts are partial, aborting at those limits and binding every page to the captured revision. Until both complete sides are available, show Partial source excerpts and independent raw readers without misleading alignment/highlights. A source revision change makes the comparison stale and disables export until reload. Keep independent source paging available; do not present mismatched excerpt offsets as comparable changed lines.
