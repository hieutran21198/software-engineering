# Framework Requirements

## Need and audience

Novel writers, narrative designers, and creators working with AI need help turning ideas into coherent story knowledge and production skeletons. One project may support several works and media without duplicating world facts.

## Confirmed rules

- Core owns stable, cross-content principles; Content owns particular creations. Stability requires impact review when constraints change.
- Preserve eight Core domains and five Content families. Novel-only work must not require gameplay, visual, or spatial decisions.
- Shared world knowledge is authoritative. Objective truth, testimony, character belief, audience knowledge, and game state are distinct.
- The framework must build a story spine and composition outline, not only classify world facts.
- Support exploration from existing ideas or drafts, sufficient knowledge for the next slice, and explicit review of contradictions.
- Provide coordinator, architect, and author skills; technical writing rules must not constrain creative prose or dialogue.
- Deliver all necessary knowledge in this repository and adopted bundle. No private source directory, external research file, or network access is needed to use it.
- Use the existing architecture catalog and safe adoption behavior. Preserve ADD as the default.

## Acceptance

1. A novel-only skeleton can be authored with the five shared Core domains and World/Narrative Content.
2. A shared example produces novel and game skeletons that reference the same canon with different revelation and agency.
3. Particular weapons, objects, and powers have World homes; playable behavior has a separate Gameplay home.
4. False belief and testimony do not change objective canon; chronology and revelation remain distinct.
5. Game choices define consequences, and a mandatory outcome remains understandable without optional lore.
6. A Core revision identifies affected content and reviews its impact rather than silently changing a rule downstream.
7. The bundle includes complete guidance, skills, templates, and examples with valid portable links and downward navigation.
8. Listing, selection, custom output, dry run, repeated adoption, and consumer conflict protection work for the new architecture.
9. Repository Go checks and the documentation production build pass.

## Boundaries and self-check

Framework authoring is distinct from downstream creative production and from ADD delivery. The new artifact owns the added bundle and catalog integration; this does not introduce an execution dependency on ADD or Artifact Plane. Requirements reflect the approved plan, have observable acceptance scenarios, and do not prescribe a universal plot formula. KISS and clear technical writing have been applied. No unresolved Requirement blocker remains.
