# Story-Driven flow inventory requirements

## Outcome

Actors can discover the existing Story-Driven authoring, revision, impact and adoption journeys through evidence-linked flow knowledge.

## Requirements

- S1: Describe named journeys from shipped Story-Driven guidance and adoption implementation. Do not invent creative facts, rewrite canon, or require optional game/art/level domains for novel-only work.
- S2: Own the inventory in project artifact specifications, using the ADD flow format. Reference framework contracts, relevant shipped guidance, implementation, and tests.
- S3: Distinguish documentation, static evidence, observations, and inference. Explain uncovered branches and boundaries; no claim of exhaustive execution-path discovery is required.
- S4: Preserve the complete existing framework baseline, delivered 1.0.0 snapshot, examples, and originating delivery evidence. No Story-Driven bundle behavior change is included.

## Local acceptance

The inventory covers authoring, revision with impact, and adoption. Referenced sources exist and support stated steps. Optional-domain boundaries remain clear. New knowledge contains no copied historical delivery tasks.

## Impact and self-check

ADD owns the flow input contract; Plane owns its reader/index/view. Prepare against artifact-driven change-flow-discovery and recheck the established contract before dependent inventory delivery. The flow-format prerequisite is a knowledge dependency, not a creative or runtime prerequisite. KISS and STE checks passed; no Requirement blocker remains.
