# Git-backed knowledge and cohesive ADD ownership

## Recovery basis

Observed choices are recovered from current sources. Historical reasoning and original approval are not inferred. Boundary registration in ADR 001 is a proposed organizational decision for this change; existing runtime behavior is unchanged.

## Context

Current guidance uses complete artifact snapshots, one active change, explicit contracts, five phase gates, task evidence and Git/PR publication. The repository supplies ADD guidance, roles, adoption and publishing together. It has no ADD runtime or workflow database.

## Decision

Recover the existing Git/Markdown method and its human/agent gates. Propose one artifact-driven artifact for the cohesive capability, including its supporting delivery responsibilities. Keep Artifact Plane independently owned. Do not create a self-edge or independent artifacts for each documentation chapter.

## Alternatives considered during recovery

A database/workflow engine would add a second state owner. One artifact per chapter or package would turn internal source structure into artificial prerequisites. A single artifact for the whole repository would conflate ADD with the explorer.

## Consequences

Future ADD changes can use complete knowledge and ordinary Git evidence. One capability can later be split through an approved change if independent contract ownership becomes necessary. Prose gates are not executable enforcement.

## Evidence

Repository-relative source paths: docs/artifact-driven/01-foundation/principles.md and artifact-model.md; 02-methodology/workflow.md and dependencies.md; 03-execution/README.md; repository AGENTS.md.

## Applicability in this change

For future versions, specifications/task-retention.md replaces requirements to copy or inherit tasks and version-specific task evidence. Existing delivered records remain unchanged.
