# Reusable model meaning

## Need and scope

Readers must identify the models inside an artifact and understand their role in a maintained journey. A knowledge document may define several models; its path is not a model identity. Existing element-reference reasons explain consumption without changing artifact prerequisite semantics.

## Acceptance criteria

- M1: Each declared model has an owner, stable local identity, understandable purpose and resolvable supporting knowledge. A model can participate in several flows without copied definitions.
- M2: A flow names participating models and explains actions and outcomes between them, including cross-artifact participation with explicit source selection.
- M3: Evidence basis and missing/ambiguous targets remain explicit. Participation never creates an artifact dependency or task prerequisite.
- M4: Legacy flows and established knowledge remain readable without model declarations. Canonical guidance, shipped bundle and adoption remain consistent.

## Discovery and self-check

The existing system-flow format identifies steps and document/code support, but defines no stable semantic model node. The artifact foundation distinguishes artifacts, changes and versions. Preserve those owned terms and existing documented/static/observed/inferred evidence meanings. KISS uses additive Markdown metadata and existing support selectors; STE keeps purpose and outcome concrete. No Requirement blocker remains.
