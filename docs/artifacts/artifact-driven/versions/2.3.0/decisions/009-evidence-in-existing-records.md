# Record explicit evidence in existing knowledge

## Decision

Add optional structured check and publication records to existing task, phase, root and unit Markdown. Keep narrative check detail and source references. Retain legacy prose readers and reject invalid explicit records without favorable fallback.

## Alternatives and reasons

More regular expressions remain sensitive to phrasing. A separate execution database duplicates authoritative evidence and violates the knowledge-only boundary. Structured facts in existing files make interpretation stable while preserving Git history and ordinary reading.

## Consequences

ADD must publish the contract before Plane consumes it. Schema validity does not verify execution, authorization or remote merges. Readers must retain source resolution and protected-ref checks. Existing snapshots need no migration.
